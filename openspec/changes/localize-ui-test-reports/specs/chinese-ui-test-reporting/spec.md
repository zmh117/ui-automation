## ADDED Requirements

### Requirement: 自动与离线中文报告
系统 SHALL 在测试报告结束时自动生成中文测试报告和中文失败报告，并提供读取既有运行目录的补生成入口，保留所有原始产物且不重新操作页面。

#### Scenario: 已有结果补生成
- **WHEN** 用户指定存在计划和结果的运行目录
- **THEN** 系统生成两份中文 Markdown，原始 JSON、英文快照、截图和 trace 内容保持不变

#### Scenario: 后续运行自动生成
- **WHEN** 正常运行、筛选运行、计划模式或可正常收尾的中断进入报告结束阶段
- **THEN** 系统自动生成两份中文报告并输出报告入口

### Requirement: 准确表达结果边界
系统 SHALL 分别报告通过、失败、超时、中断、跳过和未执行，区分仅计划、筛选范围与完整确认目录，不把非法候选本身记为测试失败。

#### Scenario: 中断的全量运行
- **WHEN** 计划有 2453 条，结果为 826 通过、2 失败、1 中断、1624 未执行
- **THEN** 报告准确显示上述数量并声明未完成，不把中断当作产品缺陷

#### Scenario: 不完整或损坏证据
- **WHEN** summary 缺失或与结果不一致
- **THEN** 报告标记证据不完整，不宣称全量通过
- **WHEN** 原始 JSON 无法解析
- **THEN** 命令以中文错误失败，保留原始文件

### Requirement: 中文场景与证据解释
系统 SHALL 为当前目录提供中文场景说明，为非通过用例展示设计步骤、实际失败检查点、预期和实际、影响说明及可用证据入口；设计步骤与执行记录必须区分，推断不得当作已证实根因。

#### Scenario: 已知分页断言
- **WHEN** 新增清空搜索跳末页用例的错误明确显示当前页预期 2、实际 1
- **THEN** 报告说明新增后未定位第二页，给出边界前置、复现步骤和证据，并标记根因仍需源码或 trace 核验

#### Scenario: 未识别错误或附件缺失
- **WHEN** 用例失败原因不能由当前解析器解释，或证据文件缺失
- **THEN** 使用中文说明局限，保留错误原文并标记缺失附件，不编造页面实际状态或链接
