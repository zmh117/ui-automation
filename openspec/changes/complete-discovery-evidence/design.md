## Context

已有发现器按计划打开控件并生成待确认草稿，扫描仅处理主文档。用户明确要求补齐四类缺口，允许必要重构及不兼容旧发现数据；仍沿用只读扫描和指定入口，不保存业务配置。

## Goals / Non-Goals

**Goals:** 弹框归属可核对、选项完整性可机器判断、Frame/开放 Shadow 边界可进入、显示文本与业务值分开采集；用本项目实例实跑。

**Non-Goals:** 不自动翻页或滚动穷尽数据，不突破闭合 Shadow root，不从 DOM 推导业务规则，不自动把观测文本认定为正确，不修改既有 PICT 选例模型。

## Decisions

1. **统一定位结构。** DOM 地址由根内 CSS 与开放 Shadow 宿主路径组成；Frame 路径由逐层 iframe 的 DOM 地址组成。入口和回放使用同一精确地址解析，不用跨根的全局同名定位。报告版本为 2，计划增加 schemaVersion=2，旧结构明确拒绝。
2. **两层采集。** 文档扫描器递归开放 Shadow roots；Playwright 协调器按扫描范围内的可见 iframe 递归采集，包含跨源子 Frame。保存各文档 URL、Frame 链及扫描状态。最大 Frame 数、深度、Shadow 深度、控件和单元格数有预算；无法进入和预算不足记为部分发现。
3. **弹框关联。** 指定 expected 必须为目标弹框根。点击前目标不可见，点击后目标唯一可见，才记录入口、弹框、父弹框、Frame 和步骤的关联。扫描范围为原 scope 加关联弹框；不把其他已打开弹框当本次结果。关闭后的关联弹框不再强制扫描。
4. **选项完整性。** 每个选项控件记录 status/source/observedCount/totalCount/reasons。原生 select 的完整 DOM 选项可以标记 complete；自定义列表依据一致的 aria-setsize 与完整、不重复的 aria-posinset 证明当前声明集合，否则为 partial 或 unknown。加载中、数量不足、证据矛盾或截断不能为 complete。该结论仅针对当前控件声明集合，不证明系统业务全集，仍须确认有限值域。快照之间不拼凑全集。
5. **单元格证据。** 普通 table 和 ARIA grid/table 记录表、行、列位置、显式业务键、可见显示文本与文本截断；只有明确的 data-discovery-value JSON 才记录 businessValue，来源为显式 DOM 声明。未知业务值为 null/false。单元格不变成可枚举配置因子，显示断言来自独立预期。
6. **项目实例。** 增加独立“发现验证”页面：范围外两层 Teleport、无关同名弹框、完整/远程加载/分页/虚拟片段/未知选项、开放和闭合 Shadow 示例、重复字段名的 iframe（含嵌套、Shadow 内 Frame、跨源测试）、带单位与精度的表格。原六页与全部组件页保持既有组合范围。

  P[指定场景和入口] --> C[Frame 协调与弹框关联]
  C --> S[文档与开放 Shadow 扫描]

## Risks / Trade-offs

- 页面异步加载或 Frame 脱离 → 明确记录不可用，不静默丢失；场景 ready 由计划提供。
- ARIA 总数错误或只代表搜索结果 → 标记来源和声明范围，核验序号一致性，不提升为系统全集。
- 闭合 Shadow 和 Canvas 无法通用读取 → 报告明确边界，需要业务组件提供适配。
- 页面结构改变使结构性地址失效 → 定位证据标记弱地址；遇到歧义停止，推荐稳定 testid。
- 读取 displayText 不能证明像素布局正确 → 单元格显示断言使用业务预期；截图用于必要的视觉复核。

## Migration Plan

更新项目内所有发现计划与测试，重新生成发现报告和确认文件；不提供旧版解析或转换层，不删除用户已有方案文档或历史运行证据。
