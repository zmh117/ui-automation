## Context

现有 Vue 指令通过父作用域拼接源码路径；节点数据的业务键在 basic.id。自动化已有可见 DOM、Frame/Shadow 定位和快照关系模型。

## Goals / Non-Goals

**Goals:** 缩短公共生成标识，保留实例区分；以当前工作流观察解析节点；识别歧义并停止；少改前端。

**Non-Goals:** 不修改业务数据、后端或逐单元格标记，不以扫描值充当独立业务断言，不做全系统菜单翻译。

## Decisions

- 常用 PI 路径采用显式业务别名。其他超长名称保留可读首尾和完整原名的确定性摘要，不直接截断、不按 DOM 顺序编号；短名不保证全局唯一，执行仍校验作用域内唯一。原有显式手写标识优先。
- EBR 三个 MdNode 调用点使用 basic.id；公共节点模板暴露 ID、名称、类型、后继 ID 的少量 DOM 属性，工作流画布增加读取入口。不暴露整个 Vue 状态。
- 读取器仅采集可见工作流及节点，输出带 URL、上下文、完整性和当前定位地址的 JSON。连接来自明确的 DOM 后继数据，不从页面布局猜测。
- 查询只接受业务名称、类型与前驱/后继条件，不接受动态 ID。纯 JSON 查询可用于分析；执行 API 每次重新读取、唯一匹配，并在动作前复核快照；变化时失败，由调用方决定下一步，不盲目重试动作。
- 同名节点通过连接关系消歧；重复 ID、未知后继、截断、不完整读取及多匹配一律停止。每个工作流单独限定，不能跨图用节点数字定位。
- 正式 runner 增加 `--suite mes --cases <文件>`，使用独立 Playwright 配置与报告。用例只描述打开页面/入口、工作流业务查询、结果面板及独立字段预期，不引入通用操作脚本语言或自动推导业务规则。收集阶段校验用例；计划模式不打开浏览器。每条用例新上下文、单 worker、零重试；可载入指定 storageState，不输出登录文件内容。
- MES 结果独立记录计划、尝试、失败和未运行数量；不计入练习站配置覆盖。操作前附上当前 JSON，失败后再采集的 JSON 明确标为失败现场。UI 断言只轮询读取，不重试点击；不提供保存、提交等动作。

## Risks / Trade-offs

- 名称与类型仍可能重复 → 强制唯一性，允许增加前后关系约束，不能使用 first。
- 长名摘要存在理论碰撞，旧代码也有重复实例 → 保留当前 DOM 唯一性验证；不以短名本身保证身份。
- 真实后端不可用 → 使用实际 Vue 模板与组件依赖的本地浏览器回归，单独报告真实业务联测缺口。
- 标识变更影响旧脚本 → 更新文档、示例及测试，重新采集 JSON，不提供旧长标识兼容。
