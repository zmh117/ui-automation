## ADDED Requirements

### Requirement: 简短标识保留作用域
系统 SHALL 集中缩短 EBR/JTH 生成标识，保留页面、区域、功能与必要实例区分，不使用 DOM 顺序或随机值解决重复。

#### Scenario: 深层公共组件及重复实例
- **WHEN** 两个不同作用域使用同一控件，或长路径仅中间片段不同
- **THEN** 标识确定且可区分，前缀更新同步到真实输入、触发器和转移浮层；相同作用域的真实重复不能被假装唯一

### Requirement: 工作流节点只读观察
系统 SHALL 从当前可见 DOM 输出节点 ID、业务名称、类型和明确连接关系，保留完整性证据；前端 SHALL 使用 basic.id 标记节点。

#### Scenario: 有多个判断节点
- **WHEN** 工作流包含多个不同 basic.id 的判断节点
- **THEN** 节点及形状标记在工作流内可区分，JSON 连接使用实际节点键，缺失键或重复键明确标记失败

### Requirement: 根据当前业务关系解析节点
系统 SHALL 在每次节点操作前采集当前 JSON，并使用业务条件唯一匹配；查询不得依赖上次动态 ID，歧义、不完整或过时观察 MUST 停止操作。

#### Scenario: 第二次运行 ID 全部改变
- **WHEN** 相同业务节点与关系在新工作流数据中使用不同 ID
- **THEN** 同一业务查询定位新的节点，使用其本轮地址，不使用首次运行的数字

#### Scenario: 同名和不完整关系
- **WHEN** 多个节点同名，或出现未知后继、隐藏节点、重复 ID、超出预算、采集后结构变化
- **THEN** 只有完整关系条件能消歧时允许操作，其他情况明确失败且不点击任何节点

### Requirement: 正式 MES 自动化执行入口
系统 SHALL 将当前业务节点定位接入正式 runner，校验用例后执行正常 UI 点击及独立预期断言，并输出与练习站覆盖独立的证据和结果。

#### Scenario: 计划和执行相同用例
- **WHEN** 用户通过 runner 指定 MES 用例文件并选择计划或执行模式
- **THEN** 计划模式只校验并列出用例；执行模式每次采集当前节点 JSON，按用例预期断言面板和字段，失败返回非零退出码，不重试点击

#### Scenario: 无效查询或错误业务预期
- **WHEN** 用例含动态节点 ID 查询、缺少独立预期，或运行后面板值与预期不同
- **THEN** 无效用例在打开浏览器前拒绝；实际值不符保留采集和失败证据，不将点击成功视为测试通过，不宣称真实后端或全系统覆盖
