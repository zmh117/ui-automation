## ADDED Requirements

### Requirement: 有限分组全量与统一选例
系统 SHALL 把发现验证页的有限分组及操作场景注册到完整目录，使用已有枚举器及真实 PICT，保留候选 ID、违规原因、样本和操作路径。

#### Scenario: 全量与 n-way
- **WHEN** 生成新页全量或 N-way 冒烟
- **THEN** 全量包含各组全部有限候选；冒烟覆盖合法可行 N 元组、违规代表和有限样本，并保留全部操作场景；不足 N 个字段的组遍历全部合法组合

### Requirement: 正常 UI 与独立断言
执行器 SHALL 实际填写和点击指定文档/弹框中的控件，以预先定义的预期核对输入、隔离、取消、刷新及显示；不得写存储或直接改 DOM 帮助通过。

#### Scenario: 跨边界配置
- **WHEN** 在指定 Frame 或开放 Shadow 中填写候选值并打开局部弹框
- **THEN** 只有目标字段改变，其他同名字段保持默认；刷新恢复默认且没有保存记录

#### Scenario: 不支持的动作
- **WHEN** 遇到禁用原生选项、无翻页按钮的列表或闭合 Shadow
- **THEN** 验证原生禁用状态、正常 UI 拦截或明确限制，不强行操作；原生菜单未实际点击时明确只验证状态契约，不把展示列表和未实现的确认按钮当作保存流程

### Requirement: 运行范围与中文结果
系统 SHALL 支持单独运行新页且准确表达范围，生成中文测试和失败报告，包含现场证据及明确的未执行/失败状态。

#### Scenario: 单页完成
- **WHEN** 发现验证页全量全部通过
- **THEN** 标记该页分组全量完成，不标记整个项目全量覆盖完成

#### Scenario: 冒烟与失败
- **WHEN** 执行该页冒烟或出现失败
- **THEN** 保留 n-way 强度、选例覆盖、实际执行结果、中文场景及预期实际、Frame/Shadow 字段证据和可用截图/trace，不让采集错误覆盖原始失败
