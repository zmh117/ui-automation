## Context

现有 `ObservedControl`、`ObservedCell` 和 `DialogAssociation` 已具备可复用的扫描事实；`createDiscoveryDraft` 只收集配置字段。真实源码中 JTH `legal/index.vue` 使用 `cor_code` 行键，`legalEdit.vue` 使用 `v-model`、条件禁用及嵌套选择弹框；两套 `src/libs/test-id.js` 在真实输入、transfer 面板和行上生成标识。结构关系不能通过任意切分连字符得到，状态变化也不能直接解释为业务依赖。

## Goals / Non-Goals

**Goals:**
- 建立包含页面、文档、表单、弹框、表格、行、单元格、字段、操作、面板及选项的统一模型。
- 每个元素保留逐快照状态；每条关系指向快照及实际依据。支持查所属结构、选项归属和经过观察的打开目标。
- 发现 CLI 自动导出模型和中文说明；运行现有回归和针对真实组件约定的本地浏览器验证。

**Non-Goals:**
- 不建立图数据库、通用源码解释器或自动执行业务的规划器。
- 不从联动外观推断业务规则，不遍历未授权的保存动作；不声称真实 MES、接口、数据库或 Redis 验收。

## Decisions

1. 在现有报告之上生成独立 `ui-element-model`（自身版本 1）。报告字段为追加观察证据，保留现有版本 3 的计划和配置模型流程。模型消费报告前验证指纹，保证来源一致。
2. 身份使用页面完整 URL（保留 query/hash）、Frame 路径、文档 URL、Shadow 路径与可靠定位。未定位对象仅在当前快照中保留，不跨状态合并且不可执行。排序后的行仍依赖唯一稳定定位，不使用行号。
3. 扫描时记录真实祖先容器、所属面板及选项地址，构建器负责合并和建边。容器链按 DOM 归属；transfer 面板采用 ARIA、明确展开步骤或已核对的 md/iView `base-panel` 约定，歧义时保留限制。禁止全局取首个浮层。
4. `contains`、`has-option`、`has-popup` 表示观察到的归属；`opens` 仅来自成功步骤或成功探索的目标界面；`opens` 不授予动作执行权限。配置因子映射可按已有定位关联，不改变确认门槛。
5. 元素状态存快照引用和当时观察，不覆盖为最后一次值。模型的状态表示证据是否有限/不完整，不作为测试通过结论。关系查询支持方向与类型，不另建通用图查询语言。

## Risks / Trade-offs

- [定位随状态改变] → 保留多元素及证据，不按同名或文案强行合并。
- [同一个弹框复用于新增与多条编辑记录] → 保留每次观察的 scene/path，打开关系带快照证据，不把记录状态覆盖成弹框全局属性。
- [缺少或重复业务键] → 保持未定位，禁止行下标成为稳定身份。
- [旧报告没有新增结构证据] → 明确模型限制，建议重新扫描，不伪造缺失容器/浮层关系。
- [候选选项不全、未知值、隐藏节点] → 保留完整性及未知值；不将选项标签转成业务值，继续沿用可见性边界。
- [源码约定版本差异] → 测试覆盖已观察的两套公共适配代码形态；未知封装仍需单独适配。
