### 给 agent 的隐含关系（写用例时注意）

1. 本 DOM 为 **修改变量**；**变量编码、类型、配方程序** 均 disabled。新建态需另抓 DOM。
2. Tab「签名」激活；其它 Tab 面板 `display:none`，勿用本文件断言其它类型 Tab。
3. 写用例 **签名类型必须用下拉原文**（操作者签名 / 先操作者签名后复核者签名 / 不同操作者双签 / 登录的操作者签名 / 操作者双签且登录的操作者首先签名），禁止用「单签」「双签」代替配置名。边端抽屉标题「电子签名-双签」为执行态 UI 文案，可保留，但前置条件须写清云端签名类型原文。
4. **勾选「多人」** 后：操作者+复核人均 locked checked；**格式选项切换为操作者|复核人文案**（含两侧签名原因）；签名原因下 **操作人、复核人「选择」均可点**。
5. **未勾「多人」**（样例 A）：仅操作者 locked；复核人勾选禁用；签名原因下仅操作人「选择」可点；格式为仅操作者三选项。
6. 「自定义」与「签名原因」相互独立；自定义未勾时其下「选择」均为 disabled。
7. 样例 B 下 **确定可点**，样例 A 下确定 disabled——是否与「多人/签名原因已配」相关，DOM 仅表现差异；勾选「签名原因」后操作人/复核人原因不能为空，为空保存提示不能为空（业务规则）。
8. 「选择」菜单仅见「删除」；真正的签名原因/人员选择子弹窗 **未包含在本 DOM**。
9. 写 `#362002` 时配置侧至少覆盖：**操作者签名**（仅操作人配原因）与 **先操作者签名后复核者签名**（两侧均可配原因）；「不同操作者双签」「登录的操作者签名」「操作者双签且登录的操作者首先签名」按同归类复用断言。
